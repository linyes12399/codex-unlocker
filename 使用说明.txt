Codex 解锁启动器（Windows 使用说明）
====================================

它是做什么的
  把你电脑上已经装好的 Codex 复制一份，做成"解锁版"：
  思考强度多出 Max / Ultra，速度档多出 Fast / Ultrafast。
  原版一个字节都不会被改动，随时可以照常打开原版。

支持哪些安装方式
  * 微软商店安装的 Codex（最常见）
  * 从官网下载的 .exe 安装版
  * 装在自定义位置：用"高级用法"里的 --app-dir 指定一次即可
  已验证的版本：26.928.x、26.930.x。
  官方更新到更新的版本后如果对不上，启动器会明确提示，
  并且只解锁能解锁的部分，不能解锁的部分保持原样，不会把应用改坏。

不想装 Node.js？用单文件版 Codex解锁版.exe
  发行包旁边有一个 Codex解锁版.exe（约 89 MB），它把 Node.js 直接嵌了进去：
  * 双击它即可运行，参数和 bat 完全一样（比如 Codex解锁版.exe --self-test），
    电脑上不需要装 Node.js，也没有"找不到 Node"的问题。
  * 第一次运行它也会自动创建桌面/开始菜单图标，图标直接指向这个 exe。
  * 注意两点：
    1) 它没做数字签名，第一次运行 Windows 可能弹蓝色提示，
       点"更多信息" -> "仍要运行"；杀毒软件（如 360）提示时选择"允许"。
    2) 它要和"启动Codex解锁版.bat"二选一使用：
       两个入口都会更新桌面图标指向"最后一次使用的那个"。
  * 没有这个 exe 或不想要它，用 bat 就行，功能完全一样。

第一次使用
  1. 把压缩包整个解压出来（右键 -> 全部解压）。
     不要在压缩包里直接双击运行。解压到哪儿都行，
     路径里有中文、空格都没关系。
     解压出来后请保持文件原样：lib 文件夹和里面的文件都不能删，
     删了会提示 [E2]（找不到 Node.js）。
  2. 如果压缩包是从网上或聊天软件下载的，解压前先做这一步：
     右键这个 zip 文件 -> 属性 -> 最下面勾上"解除锁定" -> 确定。
     它的作用是去掉 Windows 给下载文件加的安全标记，
     免得运行时老弹"安全警告"。没有这个勾选框就跳过。
  3. 彻底退出 Codex（屏幕右下角托盘图标 -> 右键 -> 退出）。
     原版和解锁版不能同时开着。
  4. 双击"启动Codex解锁版.bat"。
     第一次要复制并处理一份 Codex（约 2 GB，一到两分钟），
     窗口里会有中文提示，请不要关掉它。
  5. 成功后会自动出现"Codex 解锁版"图标（桌面和开始菜单各一个）。
     以后就点这个图标启动。想放到任务栏：
     右键图标 -> 固定到任务栏。

以后怎么用
  * 点"Codex 解锁版"图标即可，也可以双击"启动Codex解锁版.bat"。
  * 官方 Codex 更新后，下一次启动会自动重新生成解锁版。
  * 如果解锁版窗口还开着，启动器不会强行更新，会提示你先关掉。

快捷方式和文件夹搬家
  * 本工具的图标叫"Codex 解锁版"，和原版的"ChatGPT"图标不一样。
  * "Codex 解锁版"图标在桌面和开始菜单各一个。它的目标是系统自带的
    cmd.exe（这样不会被 bat 的"安全警告"拦下），参数里不带任何附加参数；
    要带参数运行请用下面的"高级用法"。
  * 图标文件放在 %USERPROFILE%\ChatGPT-Patched\Codex解锁版.ico，
    第一次从你装的 Codex 里复制出来，官方更新后也不会变样。
  * 整个文件夹挪到别处以后，双击一次"启动Codex解锁版.bat"，
    图标就会自动指向新位置。
  * 开始菜单里的"ChatGPT"图标是应用自己生成的，它可能指向解锁版副本，
    而且不会先检查更新。建议统一用"Codex 解锁版"图标。

权限相关（都不需要管理员）
  * 不需要管理员权限，也不要用"以管理员身份运行"。
  * 只会写你自己的用户目录（见下面"会改动电脑上的哪些东西"）。
  * 杀毒软件或"受控文件夹访问"拦截时，把本文件夹加入允许列表再运行。
  * 公司电脑禁用 PowerShell 时：解锁版本身照常可用（找安装、找 Node 都不依赖
    PowerShell），图标通常也仍然会自动创建——启动器会先用 Windows 脚本宿主
    （cscript）取桌面/开始菜单目录，再不行就按常见位置（本用户目录下的 Desktop、
    OneDrive 的 Desktop/桌面、开始菜单 Programs）推断。如果 PowerShell 和脚本宿主
    都被禁用，图标一定建不出来（窗口里会提示"创建失败"或"无法获取桌面/开始菜单
    目录"），这时手动建一个即可：
    右键"启动Codex解锁版.bat" -> 发送到 -> 桌面快捷方式。
    （注意：图标本身仍能用镜像里的 Codex解锁版.ico，手动建好后可以右键属性里换成它。）

遇到这些窗口怎么办
  * "Windows 已保护你的电脑"（蓝色）：点"更多信息" -> "仍要运行"。
  * "打开文件 - 安全警告"（黄色）：点"运行"。
    （也可以按前面第 2 步先"解除锁定"，以后就不弹了。）
  * 窗口一闪而过（正常情况下失败会停住让你看提示，一闪而过多半是被系统或
    杀毒软件拦下了）：双击"诊断报告.bat"看原因。
  * 提示"另一个启动器正在运行"：等一两分钟再试，可能正在首次生成。
  * 提示磁盘空间不足：用户目录所在的盘至少留 5 GB，清理后再试。
  * 提示"重建失败"/"该版本此前重建失败"/"磁盘空间不足"/"Codex 正在运行，跳过更新"：
    这些是"镜像需要更新但这次没更新成"的几种情况（窗口会停住，退出码 2；
    磁盘空间不足的处理见上一条）。当前能启动就先用着；想立刻更新：把 Codex
    完全退出（托盘右键 -> 退出）后重新运行一次；"该版本此前重建失败"的要在
    换用新版启动器后用 --force 重试。
    例外：如果解锁镜像本来就缺失、重建又没成功，启动器会退回打开原版（未解锁）、
    以退出码 1 结束并多打印一段求助提示——这种情况下当前版本用不了解锁功能。
  * 双击后解锁版窗口没出来：多半是原版 Codex 还在后台运行。
    先在托盘里彻底退出 Codex，再点一次图标。
  * 直接双击压缩包里的文件时被提示先解压：这是正常保护，
    请把压缩包完整解压后再运行。
  * 窗口提示"无法获取桌面/开始菜单目录"：这台电脑的 PowerShell 和脚本宿主
    都被禁用了，而且常见位置也不存在——解锁版本身仍可用，只是图标建不出来；
    手动建一个即可（见"权限相关"一节）。

错误码 [E1] [E2]
  [E1] 没找到 codex-launcher.js
       压缩包没有解压完整。把整个 zip 重新解压到一个新文件夹再运行。
  [E2] 没找到可用的 Node.js
       先装好官方 Codex（商店版或官网版）再运行；或者自己装一个
       Node.js（https://nodejs.org，LTS 版即可）再运行。
  窗口里出现"指定的安装目录不可用"（退出码 1）
       你显式给了 --app-dir（或 CODEX_APP_DIR）指的那个目录不是有效的
       Codex 安装，启动器不会改用别的安装、也不会静默放行，而是直接报错退出。
       检查该目录下有没有 app\resources\app.asar（或 resources\app.asar）；
       路径里不要带 & 等会破坏命令的特殊符号（详见"高级用法"）。
  窗口里出现"提示: 状态里记住的安装目录已失效"（不影响启动）
       你以前用 --app-dir 指定过一次、启动器记住了它，后来那个目录被移动或
       卸载了。这不是报错：本次会改用其它来源照常启动。不再需要这条记录时，
       运行一次 --app-dir=（等号后留空）清除即可。
  其它失败都会在窗口里用中文说明原因；按提示处理即可。

用 cc-switch 时：Ultrafast / 401 报错
  v14 起解锁版自己带了一份补全 Ultrafast 的模型目录，放在解锁版目录里
  （model-catalog-merged.json），不再往你的 config.toml 写一行字。
  所以：cc-switch 怎么切换供应商、怎么切路由，都不会把它抹掉。
  顺带说明这份目录的代价（副作用但无害）：解锁版启动应用时多加了一个参数，
  让 Codex 用解锁版自己那份目录；那份目录 = 应用自带的模型 + 你自己的模型
  （config.toml 里指定过的那份目录文件，以及 cc-switch 的
  cc-switch-model-catalog.json）合起来的超集。两点要知道：
    * 即使你用应用自带的供应商（不经过自定义目录），这份目录也照样生效：
      模型还是原来那些，只是给它们补上了 快速 / 超快（Fast / Ultrafast）档。
    * 你自己的自定义模型一个都不会少，只是不会给它们补档位
      （第三方模型带档位可能被中转站拒绝）。
  排查提示：如果你自己那份目录文件里有一项缺必填字段（例如 shell_type），
  Codex 会整份拒绝、报缺少字段（missing field）导致起不来；先把你自己那份
  目录文件修好。这不是解锁版造成的：那份坏目录不装解锁版也一样会让 Codex 报错。
  1. 用路由模式（cc-switch 开"路由"）时选 Ultrafast：
     解锁版会给请求带上 service_tier（选 Ultrafast 是 "ultrafast"、选 Fast 是
     "priority"），这一点对第三方中转站成立。
     中转站后台显不显示 ultrafast 由中转站决定；如果请求带了、后台还是
     default，那是中转站或上游没有采用这个参数，需要问中转站。
     注意：如果你在用的是"官方登录"（在 cc-switch 里用 ChatGPT 账号登录，不是
     第三方中转站），解锁版同样会补上档位，而档位会跟着请求发到官方地址去。
     不想这样的话，在 cc-switch 里改用第三方供应商即可；
     或者用原版 Codex 跑官方登录（解锁版是给第三方中转站用的）。
  2. 关掉路由模式后报 401 API_KEY_REQUIRED（直连中转站）：
     这是 cc-switch 给供应商写的 requires_openai_auth = false、又没填 Key
     造成的——请求里没有 Authorization 头，中转站当然拒绝。
     解锁版已在启动时自动改用你 auth.json 里的 Key（不写进 config.toml），
     正常情况不会再报 401。
     想彻底根治：在 cc-switch 里编辑当前供应商 -> 把配置里的
     requires_openai_auth = false 改成 true（或者干脆把 API Key 填上）-> 保存。
  3. 怎么确认修复生效了：双击"诊断报告.bat"，在输出里找这几行
     （每行开头都有个 [launcher] 前缀，找关键词即可）：
       网络修复补丁: 镜像已包含 401/Ultrafast 修复补丁 (……)
       供应商表 [model_providers.custom]: 存在  requires_openai_auth: false ...
       诊断结果: <诊断代码> - <一行说明>
       合并目录（会写入的覆盖）: ……，含 N 个带 Ultrafast 档的模型
     第一行说明补丁在；第二行是你当前供应商的实况（是不是没有填 Key）；
     第三行会写明解锁版怎么判断这个供应商（例如"检测到 …… requires_openai_auth = false
     且没有填 Key（请求会 401 API_KEY_REQUIRED）：解锁版已在启动时自动改为使用
     auth.json 里的 API Key"）；第四行 N 大于 0 说明 Ultrafast 档补上了。
     若是 401 那种情况，解锁版已替你处理，不用做别的。
     （正常启动的窗口里也会打一行"网络修复： <同样的说明>"；诊断报告里这行叫"诊断结果:"。）
  4. 已知情况（启动后中途换供应商）：解锁版是在**启动的那一刻**按当时的供应商
     算好修复参数的，之后不再变；而 Codex 每开一个新对话都会重新读一次配置。
     所以会话中途在 cc-switch 里换供应商，可能出现两种现象：
       * 换成另一个"同样没填 Key"的供应商：新开的对话会再报最初的
         401 API_KEY_REQUIRED（那条鉴权修复是给上一个供应商写的）。
         处理办法：把解锁版完全退出，重新运行一次（它会按新供应商重算）。
       * 换成"官方登录"、而且 cc-switch 把 [model_providers.xxx] 整段删掉了：
         新开的对话可能报 provider name must not be empty。
         处理办法一样：重新运行一次解锁版。
     启动解锁版时窗口里会提示一次这一条（"如果在 cc-switch 里换成另一个
     同样没填 Key 的供应商……"，同一个 config.toml 只提示一次）。
  5. 升级到 v14 后第一次启动会重新生成解锁版（一到两分钟），
     之后每次启动都会快很多（第二次起用缓存，不再重新检测安装）。
  6. v13 曾在 config.toml 开头加过一行
     model_catalog_json = "...\model-catalog-ultrafast.json"。
     v14 不再需要它。不过要注意：别只删文件、不删那一行。
     config.toml 里那一行还在、而 ~/.codex\model-catalog-ultrafast.json 被删掉时，
     直接读这份配置的 Codex（包括 VS Code 扩展）新建对话会报
     「系统找不到指定的文件」（os error 2）——解锁版自己的目录覆盖在位时能盖住，
     别的客户端盖不住。要清理就两样一起处理（任选其一）：
       * 都留着（最省事；解锁版不再用它，留着不影响）；
       * 或者先删掉 config.toml 里那一行、再删那个文件（顺序反过来会有一段空窗）；
     只删文件、留着那一行是最容易踩的坑。
     （解锁版启动时、以及"诊断报告.bat"里，遇到这种悬空行都会中文提示。）

诊断报告.bat
  遇到任何问题，双击"诊断报告.bat"。
  它只做检查，不在你电脑上留下任何改动，结果会打印在窗口里；
  把整段文字复制出来发出去，就能定位绝大多数问题。

会改动电脑上的哪些东西
  %USERPROFILE%\ChatGPT-Patched\
      解锁版副本、状态文件 launcher-state.json、
      图标文件 Codex解锁版.ico、锁文件 launcher.lock（只在运行时存在）、
      model-catalog-merged.json（解锁版自己的模型目录，带 Ultrafast 档）
      codex-launcher-overrides.json（解锁版自己的设置，只写路径，不写 Key）
      node-path.txt（上次用过的 Node 路径，用来加快下次启动）
  %USERPROFILE%\ChatGPT-Patched\app
      解锁版副本本体（打了解锁补丁的 Codex）
  %USERPROFILE%\ChatGPT-Patched\app.old
      上一次的解锁版（更新时留着，可以随时删）
  桌面 + 开始菜单
      "Codex 解锁版"快捷方式各一个
  %USERPROFILE%\.codex\config.toml
      v14 起不再改动！用 cc-switch 切换供应商也不会被解锁版影响。
  * 商店版 / 官网原版的安装目录一个字节都不会改。
  * 如果你以前用过 v13：那时写进 config.toml 的 model_catalog_json 一行
    现在用不上了（留着也不影响，解锁版自己的目录优先级更高）。

卸载
  1. 关掉解锁版窗口。
  2. 删除桌面和开始菜单里的"Codex 解锁版"图标。
  3. 删除文件夹 %USERPROFILE%\ChatGPT-Patched。
  完了。不需要还原任何配置：v14 起不改 config.toml，
  原版 Codex 一直都在，不受影响。
  （如果你以前用过 v13、config.toml 里还留着 model_catalog_json 一行，
  想清理就删掉那一行，或用同目录的 config.toml.before-codex-launcher 覆盖回来。）

高级用法（可选，一般用不到）
  在解压出来的文件夹里，点一下"文件资源管理器"顶部的地址栏，输入 cmd 回车，
  就打开了"命令提示符"。bat 的名字里没有空格，直接写名字即可：
    启动Codex解锁版.bat --dry-run
        完整试一遍但不替换镜像、不启动、不改配置，用来排查问题。
    启动Codex解锁版.bat --self-test
        严格只读自检（"诊断报告.bat"用的就是它）：找到可用安装、并且补丁
        全部命中或者能部分解锁时，退出码为 0，否则为 1。
    启动Codex解锁版.bat --create-shortcut
        只创建/刷新桌面和开始菜单的"Codex 解锁版"图标，然后退出
        （不重建镜像、不启动）。图标被误删时可以用它找回。
    启动Codex解锁版.bat --no-shortcut
        这一次不碰快捷方式。
    启动Codex解锁版.bat --app-dir="D:\My Codex"
        Codex 装在自定义位置时，告诉启动器去哪里找；成功后会记住，
        以后点图标就行。写 --app-dir=（后面留空）表示清除记下的位置。
        两种安全写法（任选）：
          - 在解压出来的文件夹里（bat 名不加引号）：
              启动Codex解锁版.bat --app-dir="D:\My Codex"
            引号只包住路径本身、等号写在引号外面；路径里没有空格时
            引号可以省略（--app-dir=D:\Codex）。
          - 不在这个文件夹里时，把 bat 的完整路径整个加引号、参数值上也照常
            加引号即可，实测可用：
              "D:\My Folder\启动Codex解锁版.bat" --app-dir="D:\My Codex" --self-test
            但参数值不能不加引号还带 &（见下面）。
            想省心的话，可以先用环境变量把路径交进去，再启动（完全不经过
            命令行的参数解析，最稳）：
              set "CODEX_APP_DIR=D:\My Codex"
              "D:\My Folder\启动Codex解锁版.bat" --self-test
            （set 那一行里，值用引号包住是安全的。）
        千万不能不加引号地写含 & 的路径：命令会被当场拆断、后面的参数
        全部丢失，启动器可能误按普通启动处理（重建镜像、结束正在运行的
        解锁版、直接启动）。
        带空格的自定义路径要在命令行里指定一次：快捷方式图标本身的参数里
        不能带引号，所以只能这样指定。
  如果人不在解压出来的文件夹里，把 bat 的完整路径整个用双引号包住，
  参数照常跟在后面：
    "D:\My Folder\启动Codex解锁版.bat" --self-test
    "D:\My Folder\启动Codex解锁版.bat" --app-dir="D:\My Codex"
  注：在命令提示符里，上面这样写是安全的（实测）。会报"文件名、目录名或
  卷标语法不正确"的是另一种"快捷方式式"写法——把整行当成一个字符串交给
  cmd：cmd /d /c ""<bat>"" 参数，此时参数里再出现引号才会炸。你自己手输
  命令用不到那种写法（我们的快捷方式本身也不带参数）；带引号的参数只应
  出现在交互式命令行里，不要拼进 cmd /c 的单字符串形式。
  写错的参数（不在上面列表里的）会直接报错退出并给出中文提示，
  不会误把解锁版启动起来。

还会遇到什么（更新后对不上时）
  * 窗口提示"部分解锁"：
    官方版本更新后，有一部分解锁暂时对不上。启动器会把能解锁的部分
    先解锁并正常启动，没解锁的部分保持原样，窗口里会写明是哪部分。
  * 窗口提示"补丁未命中"：
    这一版官方代码变化较大，暂时解锁不了。启动器会打开之前生成的解锁版；
    如果从来没生成过，就打开官方原版。把诊断报告发出来等更新即可。

    如果服务端不认这个参数导致报错，请改用原版。
